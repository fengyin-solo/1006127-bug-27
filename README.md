# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/domain/grout/     补浆领域：取数网关、原子登记、断点续传、规则与投影
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   ├── tests/                补浆领域与服务层集成测试（Node 直接跑 TS，无需联网装框架）
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

补浆领域测试（取数兜底、幂等/越级拦截、补浆原子登记、断线续传、同源投影等）：

```bash
cd frontend
npm run test:grout       # 16 项领域测试
node scripts/run-integration-tests.mjs   # 7 项通用服务层集成测试
```

## 补浆取数与登记规则（grouting / mortar）

- **取数失败即失败**：现场取不到读数就报错并按策略重试（可恢复错误重试，设备离线快速失败），
  重试仍失败写清原因，任何情况下不用上一轮读数顶替。
- **落库前校验、原子提交**：补浆量与初凝时间必须在同一份登记里齐全，缺一项整笔退回；
  注浆记录侧与浆液批次侧在同一次快照里落库，写库失败两边一起撤销，不留半条。
- **幂等与冲突仲裁**：同一注浆编号重复提交且内容一致只记一次；已注浆确认的记录与新读数
  冲突时拒绝覆盖，冲突以现场已确认记录为准，更正须走复查。
- **越级拦截**：只有「已完成」且完成注浆确认的记录才能安排补浆，状态越级动作当场拦下。
- **超量拍板**：补入后总量不超过设计注浆量的 5% 判「补足」直接放行；确需超量必须填写
  批准人与原因，结论记「超量补入」；无设计量的历史记录豁免该判定（兼容历史注浆记录）。
- **断线续传**：批量取数登记把游标持久化，中断后已登记的不重来，只从失败那一条继续。
- **结论回写、两侧同源**：补浆结论（编号、环次、补浆量、结论）写回浆液拌制批次，
  待用批次清单与待补浆批次数在注浆页、浆液拌制页、看板取同一个投影，不分两份。
- **存量入库**：旧通用表里的注浆/浆液记录首次打开时迁移，按对应环次重新排序入库、
  同注浆编号去重；重置存储需同时清 `shield-tunnel-construction:grout-domain:v1`。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。
