# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。所有页面的行列、状态、动作、统计卡都在运行时从模块元数据取，
  全站同源，不在页面里各抄一份。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。动作有起始状态限制
  （缺省按状态链取目标的前一格，分支动作在 `actionSources` 里显式登记），越级当场拦下。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 补浆的取数与登记

补浆记录（`regrout`）与同步注浆（`grouting`）、浆液拌制（`mortar`）联动，取数与登记两个
入口共用 `local-service.ts` 里的同一份实现：

- **取数失败兜底**：读本地数据失败会重试 2 次，仍失败就把原因抛给页面展示，绝不拿上一轮
  的旧读数或示例数据顶替；存根损坏时也不会用播种数据覆盖现场数据。页面取数失败会清空
  当前列表，而不是继续显示旧行。
- **登记即事务**：一笔补浆登记 = 补浆记录 + 浆液拌制待用批次 + 源注浆记录状态，三处在
  同一个事务里同生同灭；落库前先校验（补浆量、注浆压力必须为数字，初凝时间必填且合法，
  与补浆量落在同一条记录里），写库失败就地撤销，不留半条。
- **断点续登**：批量登记逐笔落库，中途断掉时已登记的留在库里；重新提交时已登记的按
  「同一注浆编号只留一条」自动跳过，从断掉的那条接着走，失败的那几笔带着原因返回。
- **越级拦截**：注浆记录没走完「确认完成」不许安排补浆，动作状态机在服务层当场拦下。
- **待用批次对账**：登记补浆会同步在浆液拌制侧生成待用批次；补浆记录页与浆液拌制页的
  「待补浆批次」都从 `listPendingRegroutBatches()` 这一份取，两侧数量天然对得上。
- **存量重新入库**：每次取数/登记前都会把存量补浆记录按对应环次校正一遍（以源注浆记录
  的环号为准）、清掉同一注浆编号的重复记录、补齐缺失的待用批次，然后一次性落库。

### 拍板口径（冲突与超量）

- **同一注浆编号重复提交**：以已入库的记录为准（先写为准），后来的整笔退回并提示已存在的
  补浆编号，不覆盖、不合并。
- **对应环号冲突**：以源注浆记录为准，存量补浆记录按它校正后重新入库。
- **超量判定**：以源注浆记录的注浆量为基准，补浆量超过基准 20% 判超量；登记照走但打
  异常标记，由值班工程师在页面上复核。历史记录注浆量不是数字时按无基准处理，只登记
  不判超量（兼容历史注浆记录）。
